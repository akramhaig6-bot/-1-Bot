# Botmakers

لوحة عربية RTL لإنشاء وإدارة بوتات تيليجرام. مبنية بـ **React + TypeScript + Tailwind CSS + Express**، ويعمل خادم الواجهة وواجهات API على المنفذ `3000` باستخدام `tsx server.ts`.

## التشغيل

```bash
npm install
npm run dev
```

افتح `http://localhost:3000`. أمر `npm run dev` يشغّل `tsx server.ts` ويستمع على `0.0.0.0:3000`. انسخ `.env.example` إلى `.env` إذا أردت تخصيص المنفذ أو حد الرفع أو مفتاح التشفير.

لإنشاء نسخة إنتاجية وتشغيلها:

```bash
npm run build
npm start
```

## ما يفعله التطبيق

- ينشئ مساحات بوت مستقلة، من دون رسائل أو أزرار أو وسائط مسبقة.
- يحفظ رسالة `/start` يدويًا، ويتيح تعديلها وحذفها بتأكيد.
- يدير أزرار Inline وReply Keyboard، وتدفقات مستقلة ومتداخلة لكل زر.
- يتيح لكل لوحة إعداد صفحات اختيارية: تقسيمًا تلقائيًا حسب عدد الأزرار أو صفحات يدوية مع ترتيب الأزرار وصفوفها ونقلها بين الصفحات. الإعداد غائب عن البيانات القديمة ويكون معطّلًا حتى يفعّله المستخدم.
- يفصل بين أزرار الصفحات (الأولى/السابق/التالي/الأخيرة) وأزرار رجوع/الرئيسية، مع نصوص وترتيب وصفوف وموضع ومؤشر صفحة قابل للتخصيص.
- يحفظ موضع القائمة والصفحة ومكدس الرجوع والرسالة لكل مستخدم وبوت في `data/navigation.json`؛ إعادة `/start` تعيد ضبط جلسة ذلك المستخدم فقط.
- يتيح إضافة الصور والفيديو والتسجيل الصوتي والمقاطع الموسيقية إلى التدفقات.
- يعرض الإعدادات المحفوظة في محاكي تيليجرام؛ يبدأ كل زر في صف مستقل ويمكن سحبه إلى صف آخر أو تجميعه مع أزرار الصف. يتضمن المحاكي تبديل الصفحات وتجربة محلية للتدفقات والرجوع دون إرسال رسائل فعلية.
- تُحفظ الرسائل نصيًا عند الضغط على «حفظ»، بينما يُحفظ ترتيب الأزرار بعد كل سحب، وتُحفظ الوسائط بعد اكتمال رفعها. تبقى مسودات النصوص عند التنقل داخل الجلسة، ويظهر تحذير المتصفح عند محاولة إغلاق الصفحة مع تغييرات غير محفوظة.
- يتحقق من التوكن عبر `getMe`، ثم يتحقق من إمكانية `getUpdates` ويبدأ Telegram Bot API long polling.
- يقرأ التدفقات المحفوظة من الخادم عند وصول تحديث تيليجرام؛ لا يتطلب حفظ الإعدادات إعادة الربط.

## التخزين والأسرار

تُحفظ بيانات البوتات والوسائط في مجلد `data/` المحلي (وهو مستثنى من Git). لا يعيد API التوكن إلى المتصفح؛ يُخزن مشفرًا باستخدام AES-256-GCM. افتراضيًا ينشئ الخادم مفتاحًا محليًا في `data/.token.key` بصلاحيات مقيدة. إذا استخدمت `BOT_TOKEN_ENCRYPTION_KEY`، احتفظ بالقيمة نفسها بعد إعادة التشغيل؛ تغييرها يمنع فك تشفير التوكنات السابقة.

يمكن ضبط `MAX_MEDIA_FILE_BYTES` لتغيير حد الرفع التشغيلي. القيمة الافتراضية `52428800` (50 ميغابايت). تُخزّن الملفات خارج ملفات الواجهة الثابتة، وتُقدّم عبر مسارات API مرتبطة بالبوت والوسيط.

## نقاط معلنة تحتاج قرارًا منتجيًا

وثيقة التصميم تركت بعض القرارات مفتوحة. لتجنب إخفاء الاختيارات، النسخة الحالية تتصرف كما يلي:

- لا يوجد تسجيل دخول أو تعدد مستخدمين؛ البيانات مساحة محلية مشتركة. **لا تعرض الخادم على شبكة عامة قبل حسم المصادقة.**
- لا يوجد حقل اسم داخلي للبوت ولا إجراء حذف بوت كامل؛ تظهر مساحة الإعداد بمعرّفها إلى أن يُتحقق من اسم حساب تيليجرام.
- رسالة البداية نص فقط. الوسائط متاحة داخل تدفقات الأزرار.
- ينشأ كل زر جديد في صف مستقل، ويمكن للمستخدم جمع الأزرار أو تغيير مواضعها بالسحب داخل المحاكي.
- ترتيب الوسائط هو ترتيب إضافتها. حد الرفع التشغيلي الافتراضي 50 ميغابايت وقابل للضبط.
- عند وجود Inline وReply معًا للرسالة نفسها، يختار المستخدم صراحةً النوع الظاهر معها. يُعرض النوع الآخر مع رد البوت التالي الذي لا يملك لوحة فرعية خاصة به؛ ذلك لأن Telegram لا يقبل نوعي لوحة مفاتيح في `reply_markup` واحد.
- في القوائم المرقّمة، يحرّر Inline الرسالة الحالية عند اختيار ذلك، مع بديل إرسال رسالة جديدة عند اختيار المستخدم أو رفض Telegram للتحرير. أما Reply Keyboard فتنتقل دائمًا برسالة جديدة، لأن Telegram لا يتيح تحرير لوحة Reply على رسالة سابقة.
- حالة التنقل محفوظة منفصلة عن إعدادات البوت في `data/navigation.json`، ومفتاحها زوج البوت والمستخدم؛ إذا استخدم المستخدم محادثة أخرى، يبدأ النظام سياقًا جديدًا لتجنب تعديل رسالة من محادثة مختلفة.
- عند الوضع اليدوي، يُضاف الزر الجديد إلى الصفحة الأخيرة؛ نقل الأزرار بين الصفحات لا يغيّر تدفق الزر أو وسائطه. حذف الصفحة متاح بعد إفراغها لتفادي فقد الأزرار.
- تُرفض نصوص تنقل Reply المتطابقة مع أزرار Reply أو بعضها، لأن رسائل Reply تُطابق بالنص ولا تتضمن callback فريدًا.
- حذف زر يحذف تدفقه وكل الوسائط والأزرار المتداخلة التابعة له. حذف نص رسالة التدفق يُبقي وسائطه وأزراره الفرعية.
- عند فشل التحقق من توكن بديل يبقى التوكن والاتصال السابقان كما هما؛ لا يستبدلان إلا بعد نجاح التحقق وبدء polling.

تُعرض اختيارات لوحات المفاتيح في الواجهة عند الحاجة، وتُطلب قبل الربط إذا كانت غير محسومة. ما عدا ذلك، يجب مراجعة القرارات أعلاه قبل النشر العام أو توسيع المنتج.

## الاختبارات

```bash
npm test
npm run typecheck
npm run build
```

تغطي الاختبارات تقسيم الصفحات اليدوي والتلقائي، ترتيب الصفوف ونقل الأزرار، التوافق مع البيانات القديمة، رفض تعارضات Reply، والتعامل مع التنقل والمكدس لكل مستخدم عبر خادم Telegram Bot API محلي محاكى. **هذه الاختبارات لا تعني اتصالًا حيًا بتيليجرام**؛ يلزم توكن وشبكة متاحة لإثبات ذلك.
